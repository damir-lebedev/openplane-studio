## 0. Коротко

- **Сейчас делаем только раздел «Плата»**: мастер настройки → генератор
  прошивки → прошивка платы → наладка на земле. Полёты, Онлайн, Чёрный ящик
  и Грузы — страницы «Скоро», но место под них в меню есть с первого дня.
- **Шаги идут в порядке зависимостей**: плата → самолёт → датчики → пульт →
  тумблеры → безопасность → проверка → прошить → наладка. Тумблеры
  открываются только после датчиков. Режим без нужного датчика виден серым с
  надписью «Для работы режима RTH нужны датчики: GPS» и кнопкой «Добавить GPS».
- **Прошивка получается в два этапа.** Этап 1: приложение подставляет
  значения в `Config.h`, `Controls.h`, `Channels.h`, `SensorSelection.h` в
  копии исходников и собирает PlatformIO — работает с прошивкой как она есть.
  Этап 2: одна готовая прошивка на плату плюс параметры в памяти платы —
  прошивка за секунды, реверс элерона без перепрошивки, PlatformIO у
  пользователя не нужен.
- **Стек:** Tauri 2 (внутри Rust) + React + TypeScript + Three.js.
- **От тебя нужны ответы** из раздела 8.

## 2. На что жалуются на форумах — и что делаем мы

| Жалоба | Что делаем |
| --- | --- |
| Windows не видит плату в DFU: ставь Zadig или ImpulseRC Driver Fixer, и то помогает не всем | драйвер WinUSB для «STM32 BOOTLOADER» ставит само приложение, одной кнопкой; рядом — что сейчас видит Windows |
| «Не армится, и непонятно почему» — флаги RXLOSS, ANGLE, THROTTLE… | причина по-русски и кнопка «исправить» |
| После обновления прошивки слетели настройки; старый `diff` не ложится на новую версию (в INAV 6 переименовали много параметров) | настройки живут в проекте на ПК, прошивка собирается из него; перед прошивкой — бэкап калибровок с платы; при смене версии — миграция с отчётом |
| Нет самолётных умолчаний: у INAV высота возврата 10 м — для самолёта мало | шаблоны самолётов с разумными числами; первый — твой Astro-Cargo |
| Часть настроек не вынесена в интерфейс, только в CLI | «Полный» режим строится из описания параметров прошивки: забыть параметр нельзя |
| Облачная сборка Betaflight: гоняешь галочки опций туда-сюда, пока прошивка не заработает | опции не выбираются руками — следуют из выбранного железа |
| Миссия «от дома» врезается в холм: путают высоту от дома, над морем и над рельефом | (Полёты) профиль рельефа под маршрутом и красная зона там, где запас над землёй мал |
| Mission Planner работает только под Windows | сначала Windows, потом Mac и Linux той же сборкой |
| Видео с логом подгоняют вручную по писку ARM; Chrome плохо перематывает H.264 с B-кадрами | (Чёрный ящик) синхронизация по времени и GPS; перекодирование видео одной кнопкой |
| Кривую калибровку компаса программа не показывает — самолёт уводит | проверка компаса: курс платы против курса по карте, помеха от мотора на газу |
| Триммеры пульта не в нуле — прошивка считает это командой | на шаге «Пульт» приложение видит нецентрированные стики и предупреждает |

## 3. Свои идеи

1. **Живой пульт.** Плата подключена — тумблеры на картинке двигаются вместе
   с настоящими. Назначение: «щёлкни тумблером, который хочешь занять» —
   приложение само видит канал и число положений.
2. **Мастер проверки рулей.** 3D показывает, куда должен пойти руль: «правый
   стик вправо — правый элерон ВВЕРХ. Так?» [Да] [Нет — перевернуть]. «Нет»
   ставит флаг из блока «Реверс»: конфиг, а не провода. Затем то же для
   стабилизации: «наклони самолёт вправо — правый элерон должен пойти вниз».
3. **Режим стенда одной галочкой.** Сейчас предел газа под слабую батарею —
   правка `THROTTLE_LIMIT_PCT` туда и обратно (коммиты d9c9305 → c0a15f4). В
   приложении — галочка «Стенд: газ ≤ 50 %», красная плашка, пока её не
   снимешь, и предупреждение на экране «Готов к полёту».
4. **Сводка по-человечески перед прошивкой**: «SwC вверх — ручной, середина —
   стабилизация, вниз — автовзлёт. Пропадёт связь в воздухе — полетит домой на
   40 м и будет кружить; без GPS — планирует, нос −3°. Дальше 500 м — домой».
5. **Проверка failsafe приёмника.** FS-iA6B при потере связи продолжает слать
   кадры — прошивка ловит это по газу ниже 950 мкс. Приложение: «выключи
   пульт» → ✅ «потерю связи видно» или пошаговая настройка failsafe в меню FS-i6.
6. **Схема подключения по твоему выбору**: плата → разъёмы JST-XH → модули, с
   номерами контактов; печать в PDF.
7. **Шпаргалка на пульт** — карточка «какой тумблер что делает», распечатать и
   наклеить.
8. **Подсказка входа в загрузчик для конкретной платы**: анимация «замкни BT0
   на 3V3 и нажми RST» на картинке DevEBox, для ESP32 — «зажми BOOT».
9. **«Порт занят»**: приложение находит открытый `pio device monitor` и
   закрывает его само, как я делаю сейчас.
10. **Автоопределение датчиков**: если на плате уже наша прошивка, опрос шин
    (команда `b`) сам заполняет шаг «Датчики»: «нашёл BMP581 на 0x46 и LSM6DSV
    на 0x6A».
11. **Хэш конфигурации внутри прошивки**: после прошивки приложение читает его
    и пишет «на плате ровно то, что в проекте». Подключил плату — приложение
    само открывает её самолёт.
12. **Паспорт самолёта**: прошивки, калибровки, полёты, налёт, ремонты. Из
    этого потом вырастет флот и «борт №773».
13. **Солнечная тема** — светлая и контрастная, для ноутбука в поле.
14. **Отмена и история**: Ctrl+Z, «что изменилось с прошлой прошивки», откат
    на любую.

## 4. Что не берём (и почему)

- **Всё квадрокоптерное**: фильтры гироскопа, RPM-фильтр, PID-слайдеры, рейты
  и экспо, порядок моторов, airmode.
- **Таблица портов «UART × функция»** (Betaflight) — порты следуют из
  выбранных модулей и пинов.
- **Стена галочек «опции сборки»** — опции следуют из железа.
- **Дерево всех параметров как главный экран** (у Mission Planner их около
  1200) — только в «Полном» режиме и в поиске.
- **Подстройка PID тумблером в полёте** (Adjustments) — против твоего правила
  «проверки на земле, а не перенастройка в полёте». Для живого подбора уже
  есть крутилка `STAB_GAIN`.
- **Логические условия и скрипты** (INAV Programming) — сложно, и легко
  сделать опасно.
- **Армирование стиками** — у тебя ARM на тумблере SwA; для самолётов так и
  советуют.
- **Редактор OSD, таблицы VTX, сетка LED-ленты** — в прошивке нет
  аналогового FPV и ленты; огни — одна настройка.
- **Стрелочные приборы и экран на 50 цифр** (Mission Planner) — шум.
- **Управление самолётом с джойстика ПК** — небезопасно и не нужно.
- **Галочки прошивальщика на виду**: «No reboot sequence», «Flash on
  connect», скорость порта, полное стирание — всё делается само, ручное
  спрятано у гиков (пункт 99).
- **Профили PID и батарей, переключаемые с пульта** — в INAV жалуются, что
  настройки перетирают друг друга.
- **Чужие прошивки** (Betaflight, INAV, ArduPilot) — приложение только для
  OpenPlane; с QGroundControl и Mission Planner дружим через MAVLink.

## 5. Как устроено внутри

### 5.1 Стек

| Что | Чем |
| --- | --- |
| Приложение | **Tauri 2**: интерфейс — React + TypeScript + Vite, внутри — Rust |
| 3D | Three.js через react-three-fiber, модели — glTF |
| COM-порты | Rust, крейт `serialport` |
| STM32 по USB (DFU) | этап 1 — dfu-util, которым PlatformIO уже шьёт твою DevEBox; потом — DFU прямо из Rust (`nusb`) |
| ESP32 | этап 1 — через PlatformIO; потом — крейт `espflash`, без Python |
| Драйвер DFU для Windows | libwdi (он внутри Zadig) |
| Правила и генератор | `packages/core` на TypeScript, без интерфейса, с тестами: проект, правила «что чему нужно», генератор конфиг-файлов |

Почему Tauri (решено 17.10): установщик ~10 МБ вместо ~100 МБ у Electron,
меньше памяти, быстрее запуск; USB и COM-порты — родными библиотеками Rust;
та же сборка потом пойдёт на Android (пункт 94).

Минусы, которые принимаем:

- на твоём ПК один раз ставятся Rust и Visual Studio Build Tools (компилятор
  C++ от Microsoft) — несколько гигабайт и окно с правами администратора.
  WebView2 у тебя уже есть;
- на Linux Tauri рисует через WebKitGTK, тяжёлый 3D-рельеф там может
  тормозить. На Windows это тот же Chromium, что в Edge, — разницы с
  Electron нет;
- первая сборка Rust идёт несколько минут, дальше быстро;
- готовых конфигураторов на Tauri почти нет, подглядывать не у кого — это моя
  забота.

Всё работает без интернета: в поле нужны только ноутбук и кабель.

### 5.2 Как получается прошивка

Сейчас все настройки вшиты в код прошивки. Перевернуть элерон — значит
поправить строку в `Config.h`, собрать прошивку и залить её заново. Отсюда два
этапа:

- **Этап 1:** приложение делает ровно это за тебя. Ты щёлкаешь мышкой, оно
  правит файлы, собирает и шьёт. Прошивку переделывать не надо.
- **Этап 2:** настройки переезжают в память платы, как настройки в телефоне.
  Прошивка шьётся один раз, дальше приложение отправляет новые настройки по
  кабелю за секунду, без сборки. Так устроены Betaflight, INAV и ArduPilot.

**Этап 1 — сборка из исходников (прошивка как есть).**

1. В `Config.h`, `Controls.h`, `SensorSelection.h` и `AutopilotTypes.h` у
   параметров и режимов появляются метки в комментариях:
   `// @param группа=rth ед=м мин=10 макс=500 простой` или
   `// @requires imu baro gps`. Скрипт `tools/manifest.py` собирает из них
   `manifest.json` — всё, что приложение знает о прошивке: параметры с
   умолчаниями и пределами, режимы, функции, крутилки, датчики, платы, пины и
   что чему нужно. Тест следит, чтобы у каждого `constexpr` была метка. Так
   приложение и прошивка не разъедутся: новый параметр в `Config.h` сам
   появится в «Полном» режиме.
2. Приложение берёт исходники нужной версии (сейчас — твою папку `plane` или
   коммит с GitHub, релизов пока нет), копирует в свой кэш и подставляет
   значения проекта в четыре файла. Твой репозиторий не трогается.
3. Сборка и заливка — `pio run -e <плата> -t upload`, тот же путь, которым ты
   шьёшь сейчас. Вокруг него приложение делает всё остальное: перезагрузку в
   загрузчик, драйвер, «порт занят», прогресс, понятные ошибки. PlatformIO —
   твой установленный или свой в папке приложения. Повторная сборка берётся
   из кэша.

Плюс: работает сразу и с любым параметром. Минус: каждая правка — пересборка и
перепрошивка, а у чужого человека первый запуск качает тулчейны.

**Этап 2 — без компиляции.**

Прошивка читает параметры из памяти платы (хранилище для калибровок уже есть —
`KeyValueStore`), все драйверы датчиков вшиты и выбираются параметром,
привязки тумблеров — таблица в памяти. Приложение заливает готовую прошивку
под плату и пишет параметры по USB. Реверс элерона или новый тумблер —
мгновенно. Испорченные параметры (CRC) — ARM запрещён, причина видна.

Почему не сразу этап 2: это большая переделка лётного кода (`constexpr` →
параметры), а этап 1 даёт работающую кнопку «Прошить» сразу. Метки этапа 1
потом сгенерируют таблицу параметров этапа 2 — работа не пропадёт.

### 5.3 Связь с платой

Сейчас у платы текстовая консоль (`h s i o c m p b k`, `D` — в загрузчик) и
STX-команды `bb` для выгрузки ящика. Человеку удобно, программе — нет.

Предлагаю **MAVLink 2 по USB**: он уже есть в прошивке для телеметрии.
Приложение переводит порт в «режим приложения»: консоль молчит, идут кадры —
каналы пульта, углы, датчики, причины запрета ARM, ответы на команды
(калибровки, проверка выходов, перезагрузка). Бонус: по тому же кабелю
подключится и QGroundControl. Консоль остаётся — вкладкой в меню платы.

### 5.4 Что чему нужно

Таблица уходит в манифест из меток прошивки. Сейчас она живёт в
AUTOPILOT_GUIDE, раздел «Что нужно каждому режиму».

| Режим или функция | Обязательно | Улучшает |
| --- | --- | --- |
| MANUAL | — | — |
| STABILIZE, ACRO, RESCUE | IMU | — |
| LAUNCH | IMU | барометр |
| ALT_HOLD | IMU, барометр | — |
| AUTO_LAND | IMU, барометр | компас |
| CRUISE | IMU, барометр | GPS, компас, трубка Пито |
| LOITER, RTH | IMU, барометр, GPS | трубка Пито |
| SOARING | IMU, барометр | GPS, трубка Пито |
| AUTO_TAKEOFF | IMU, шасси с колёсами | барометр, GPS, трубка Пито |
| GEOFENCE, HOME_RESET, крутилка LOITER_RADIUS | GPS | — |
| FLAPS, AIRBRAKE, крутилка FLAPS | элероны на двух сервах | — |
| PAYLOAD_DROP | серво на AUX1 | — |
| CAMERA_STAB, крутилка CAMERA_TILT | серво на AUX2 (для STAB ещё IMU) | — |
| MOTOR_REVERSE | двунаправленный ESC | — |
| крутилка CRUISE_SPEED | — | трубка Пито (тогда крутилка задаёт скорость, а не газ) |
| «домой» при потере связи | GPS (без него — планирование) | — |
| чёрный ящик | SD-карта (H743) или флеш (ESP32-S3) | — |
| MAVLink-телеметрия | свободный UART (есть на H743) | — |
| Wi-Fi дашборд | ESP32 | — |

Правила привязок — те же, что `static_assert` в `Controls.h`, но видны сразу,
а не при сборке:

- стики (CH1–CH4) и SwA (ARM) не занимаются;
- на канале одна привязка;
- тумблер выбора режимов — один;
- на двухпозиционном тумблере действие только на «вниз, к себе» (выше
  1750 мкс), «вверх» — ничего;
- ни на одном тумблере нет MANUAL — предупреждение: «главный режим
  безопасности должен быть под пальцем».

Ограничения плат: у ESP32-C3 нет руля направления, AUX, пищалки и GPS TX; у
ESP32 38 pin — экрана и датчика батареи; чёрный ящик — только H743 и S3;
MAVLink — только H743.

Каждая вещь в мастере — в одном из трёх состояний:

- ✅ доступно;
- 🟡 работает, но хуже — подпись «улучшит: компас»;
- ⛔ недоступно — серая карточка, поверх надпись «Для работы режима RTH нужны
  датчики: GPS» (для не-датчиков — «нужно: элероны на двух сервах») и кнопка,
  которая ведёт к нужному шагу.

Если вернуться назад и убрать датчик, всё, что от него зависело, краснеет, а
кнопка «Прошить» заблокирована, пока не исправишь. Клик по ошибке ведёт к ней.

### 5.5 Самолёт — это папка

`Документы/OpenPlane/Ангар/Astro-Cargo #1/`:

- `plane.json` — плата, самолёт, датчики, пульт, привязки, параметры
  (изменённые относительно умолчаний), версия прошивки;
- `history/` — снимок на каждую прошивку и бэкап калибровок с платы;
- потом `flights/` — скачанные полёты.

Текст, а не бинарник — дружит с git и сравнением. Первый проект — импорт
твоих текущих `Config.h`, `Controls.h` и `SensorSelection.h` одной кнопкой.

### 5.6 Лицензия и репозитории (решено 17.10)

- `openplane-studio` — открытый, под той же OpenPlane License, что прошивка:
  каркас, Ангар, Плата и прошивальщик, потом Чёрный ящик, Онлайн и Полёты.
- Логистика — закрытая, в отдельном приватном репозитории: сервер заказов,
  оплата, диспетчерская, флот, приложение техника.
- Как соединить — предложение, решим, когда дойдём до Грузов: вкладка «Грузы»
  в открытом приложении после входа показывает интерфейс закрытого сервера.
  Закрытый код не попадает в открытый репозиторий, а пользователь видит одно
  приложение.

## 6. Интерфейс

### 6.1 Правила против шлака

1. Слева — не больше шести разделов. Всё остальное живёт внутри них.
2. Контекст — один раз, в шапке: какой самолёт и какая плата подключена. В
   экранах он не повторяется.
3. Одно главное действие на экран, всегда на одном месте: «Далее» справа
   внизу, «Прошить» справа вверху.
4. Сложное — по запросу: «Дополнительно» и переключатель «Простой │ Полный», а
   не новые вкладки.
5. Гиковское (консоль, сырые параметры, ручные опции прошивки) — в меню платы
   и «⋯», не в навигации.
6. Недоступное не прячется, а сереет с причиной — так видно, какой датчик что
   открывает.
7. Ошибка — рядом с причиной, плюс счётчик внизу; клик ведёт к ней.
8. «Скоро» видно в меню — понятно, куда растёт приложение, — но внутри одна
   аккуратная страница, а не пустые экраны.
9. Потом разделы будут зависеть от роли: пилот видит Ангар, Плату, Полёты и
   Ящик; оператор логистики — диспетчерскую из Онлайна, Грузов и флота;
   техник — своё приложение.

### 6.2 Каркас

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ OpenPlane Studio   Самолёт: Astro-Cargo #1 v   ● DevEBox H743 · COM13 v  ? │
├──────────┬─────────────────────────────────────────────────────────────────┤
│ Ангар    │                                                                 │
│ Плата    │                                                                 │
│ Полёты * │                  рабочая область раздела                        │
│ Онлайн * │                                                                 │
│ Ящик   * │                                                                 │
│ Грузы  * │                                                                 │
│          │                                                                 │
│ Настройки│                                                                 │
└──────────┴─────────────────────────────────────────────────────────────────┘
  * — «Скоро»
```

- **Самолёт ▾** — переключатель самолёта для всех разделов сразу.
- **● Плата ▾** — статус: серый — ничего не подключено, зелёный — наша
  прошивка, жёлтый — загрузчик или чужая прошивка. В меню: порт, версия, «в
  загрузчик», «консоль», «прошить файл…».
- Подключил плату — всплывает «DevEBox H743, на ней Astro-Cargo #1 (прошит
  17.10)», самолёт выбирается сам. Незнакомая плата — «Создать самолёт?».
- Настройки внизу: язык, тема, единицы, где PlatformIO, драйверы, обновления.

### 6.3 Раздел «Плата»: шаги

```text
Плата → Самолёт → Датчики → Пульт → Тумблеры → Безопасность → Система → Проверка → Прошить → Наладка
```

| Шаг | Простой режим | Полный добавляет | Что решает для следующих шагов |
| --- | --- | --- | --- |
| 1. Плата | плата из списка или «определить подключённую»; провода или плата-носитель; пины по умолчанию видны таблицей | смена пинов (только подходящие), шины, частоты | UART-ы, носитель для ящика, MAVLink или Wi-Fi |
| 2. Самолёт | шаблон; моторы: 1 (2+ — «скоро в прошивке»), тянущий или толкающий; ESC обычный или двунаправленный; шасси: хвостовое, носовое или нет (с руки); AUX: сброс груза, камера | ходы рулей, закрылки и тормоз в мкс, реверс каждой сервы | закрылки, реверс мотора, автовзлёт, груз, камера |
| 3. Датчики | у каждого «нет» или модель: IMU, барометр, компас, GPS, трубка Пито, экран, батарея; у каждого — «что даёт: ALT_HOLD, CRUISE…»; готовые наборы | шина и адрес, ориентация IMU и компаса, фильтры трубки | режимы автопилота |
| 4. Пульт | строка сверху шага «Тумблеры»: пульт FS-i6, приёмник iBUS | раскладка и реверс каналов, порог тумблера, таймаут приёмника | какие тумблеры и крутилки есть |
| 5. Тумблеры | рецепт («Ученик», «Термики», «Доставка», «С руки») или перетаскивание на картинке пульта | у каждого режима — его числа: высота RTH, этапы взлёта, термики… | — |
| 6. Безопасность | строка в «Проверке»: «пропала связь → домой (GPS есть)» | планирование, геозабор (тумблером, всегда или нет; радиус, потолок), высота возврата, качество GPS для дома, пищалка, предел газа | — |
| 7. Система | — | чёрный ящик, MAVLink, Wi-Fi дашборд, лог, цикл | — |
| 8. Проверка | ошибки и предупреждения, сводка по-человечески, большая кнопка «Прошить» | отличия от того, что сейчас на плате; схема подключения; шпаргалка | — |
| 9. Наладка | после прошивки, см. 6.8 | — | — |

- В простом режиме шесть экранов: Плата, Самолёт, Датчики, Тумблеры,
  Проверка, Наладка. Остальное — умолчания шаблона.
- Переключатель «Простой │ Полный» — в шапке раздела. Изменённое в полном
  режиме не теряется в простом: шаг показывает «3 параметра изменены вручную».
- «Все параметры» (полный режим) — таблица из манифеста: поиск, «только
  изменённые», сброс к умолчанию; у каждого — описание, единицы, пределы.
- Ctrl+K — поиск чего угодно: «высота RTH» → переход к полю.

### 6.5 Шаг «Тумблеры»

```text
┌ Тумблеры ────────────────────────────────────── Пульт: FlySky FS-i6 v  iBUS ┐
│ Режимы:   [MANUAL] [STABILIZE] [ALT_HOLD] [CRUISE] [ACRO] [RESCUE]          │
│           [RTH░░░] [LOITER░░]   «Для работы режима RTH нужны датчики: GPS»  │
│                                 [Добавить GPS]                              │
│ Функции:  [FLAPS] [MOTOR_KILL] [PAYLOAD_DROP] [GEOFENCE░░] ...              │
│ Крутилки: [STAB_GAIN] [CRUISE_SPEED] [MAX_BANK] [RATES] ...                 │
│ Рецепты:  Ученик · Термики · Доставка · С руки                              │
├─────────────────────────────────────────────────────────────────────────────┤
│      SwA           SwB            SwC — режимы           SwD                │
│   вверх: —      вверх: —      вверх:    MANUAL       вверх: —               │
│   вниз:  ARM    вниз:  FLAPS  середина: STABILIZE    вниз:  MOTOR_REVERSE   │
│   (замок)                     вниз:     AUTO_TAKEOFF                        │
│                                                                             │
│   VrA: STAB_GAIN  x0.25 … x1 … x2        VrB: CRUISE_SPEED  30 … 55 … 85 %  │
│                 ( стик )                       ( стик )                     │
└─────────────────────────────────────────────────────────────────────────────┘
```

- Перетащи карточку на положение тумблера или кликни по положению — откроется
  список.
- SwA под замком: «ARM всегда на SwA, так устроена прошивка».
- Плата подключена — тумблеры на картинке двигаются вместе с настоящими,
  включённое подсвечивается; «щёлкни тумблером» выбирает его сам.
- В полном режиме клик по карточке режима открывает его числа (высота RTH,
  этапы взлёта, параметры термиков).

### 6.6 3D: камера-режиссёр

Каждый пункт мастера знает, на что смотреть:

| Что выбрал | Что делает сцена |
| --- | --- |
| шаг «Датчики», трубка Пито | камера наезжает на трубку, трубка подсвечена |
| «Нет» | трубка плавно растворяется |
| «2 × BMP581» | трубка возвращается в разрезе: BMP581 в герметичной полости; в фюзеляже подсвечен статический барометр |
| другая модель датчика | меняется модель модуля внутри (GY-521 → LSM6DSV…) |
| мотор толкающий | мотор переезжает назад, винт крутится в нужную сторону |
| шасси хвостовое | модель встаёт на хвостовое колесо со стояночным углом |
| ориентация IMU | плата в фюзеляже поворачивается, стрелка X чипа — к носу |
| тумблер на пульте | рули и закрылки показывают, что включилось |
| геозабор, высота RTH | полупрозрачный цилиндр радиуса и потолка вокруг модели |

Модель — Astro-Cargo v3.2 из Fusion 360 с отдельными деталями (элероны, рули,
мотор, винт, шасси, трубка, GPS, плата) → glTF. Для чужих самолётов —
упрощённая модель из частей: фюзеляж, крыло, хвост, моторы. Модули датчиков —
свои low-poly модели в одном стиле.

### 6.7 Кнопка «Прошить»

```text
Прошить
 1. сборка (из кэша — секунды, первый раз — минуты)
 2. порт занят монитором → [Закрыть и продолжить]
 3. бэкап калибровок с платы → история самолёта
 4. плата в загрузчик: наша прошивка → команда D
                       голая плата  → анимация «BT0 на 3V3 + RST» / «зажми BOOT»
 5. нет драйвера DFU → [Установить] (одно окно Windows с правами администратора)
 6. заливка с прогрессом → перезагрузка
 7. плата отвечает: версия и хэш конфигурации = проект → ✅ Готово
 8. [Перейти к наладке]
```

Каждая ошибка — одна фраза «что случилось» и кнопка «что сделать». Полный
лог — по клику «подробнее».

### 6.8 Наладка (после прошивки)

Карточки по порядку, как в «Порядке настройки нового самолёта» из
AUTOPILOT_GUIDE:

1. Датчики на месте — опрос шин против проекта.
2. Установка IMU — три позы, модель показывает, как поставить самолёт.
3. Калибровка на земле — хвост поднят, потом на колёсах.
4. Компас — вращай, сфера заполняется.
5. Рули от стиков — «так? да / нет → реверс».
6. Рули от стабилизации — «наклони самолёт вправо…».
7. Мотор — галочка «винт снят», направление, реверс.
8. Failsafe — «выключи пульт».
9. Трубка Пито — «подуй в трубку».
10. Итог — «Готов к полёту ✅» и предполётный чек-лист.

Ответы «нет» копятся, в конце — одна перепрошивка (на этапе 2 — мгновенно).

## 8. Решения и открытые вопросы

Решено 17.10:

1. **Стек** — Tauri 2 (внутри Rust) + React + TypeScript + Three.js (5.1).
2. **Лицензия** — приложение открытое, логистика закрытая (5.6).
3. **3D** — модель Astro-Cargo модульная, все детали отдельные: экспорт по
   деталям в glTF. Через Fusion MCP (17.10 он не подключился) или выгрузишь
   сам.

Открыто:

4. **Этапы прошивки** — сначала сборка PlatformIO, потом настройки в памяти
   платы (5.2)?
5. **Имя и репозиторий** — `openplane-studio` рядом с `plane`, потом
   отдельный репозиторий на GitHub?
6. **Пульты** — пока считаю: только FS-i6.
7. **Прошивка** — пока считаю: два мотора и больше, V-хвост, летающее крыло и
   покупные датчики скорости видны в интерфейсе с надписью «скоро».
